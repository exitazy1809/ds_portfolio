Darkstore

Прогнозирование недельных продаж

CatBoost · PostgreSQL · Airflow · S3

О проекте

Production-пайплайн для автоматизации прогнозирования недельных продаж магазинов и отделов.

Модель формирует прогноз weekly_sales на плановый период и сохраняет результаты в PostgreSQL для дальнейшего использования в аналитике и бизнес-процессах.

Бизнес-задача

Необходимо автоматизировать прогнозирование продаж для магазинов и отдельных отделов.

  • планирование продаж;
  • прогнозирование нагрузки;
  • аналитика магазинов;
  • поддержка бизнес-решений.

Модель

CatBoostRegressor

Градиентный бустинг используется для прогнозирования недельного объёма продаж.

Модель работает с категориальными, временными и лаговыми признаками.

Оценка качества

Для оценки модели используются:

  • RMSE
  • MAE
  • R²

Хранение модели

Обученная модель хранится в Yandex Object Storage (S3).

Важность признаков

Наиболее значимыми для прогноза оказались признаки, отражающие историческую динамику продаж:

Lag Features

  • sales_1week_ago
  • sales_2week_ago
  • sales_4week_ago

Aggregated Features

  • mean_sales_4week
  • avg_sales_before

Результаты соответствуют бизнес-логике: текущий спрос во многом определяется предыдущей динамикой продаж магазина и отдела.

Лаги и агрегаты рассчитываются только на основе прошлых данных, поэтому они не используют будущие значения целевой переменной.

Основной акцент сделан на временных и исторических характеристиках продаж.

Production Pipeline

01 — PostgreSQL

Загружаются исторические продажи, плановые даты, данные магазинов и внешние признаки.

02 — Preprocessing

Выполняется очистка данных, генерация временных признаков, лагов и rolling statistics.

03 — S3

Airflow загружает обученную модель из Yandex Object Storage.

04 — Inference

Модель формирует batch-прогноз для планового периода.

05 — PostgreSQL

Результаты сохраняются в таблицу predictions.

Airflow DAG

sales_prediction_batch_inference

  1. load_data
  2. preprocess_features
  3. load_model
  4. run_inference
  5. save_predictions

DAG запускает полный batch inference pipeline по расписанию.

Архитектура

PostgreSQL → preprocessing → CatBoost → S3 → Airflow → inference → PostgreSQL

Инженерные решения

Единый preprocessing

Feature engineering вынесен в отдельный модуль preprocessing.py.

Model Storage

Модель не хранится внутри DAG, а загружается из S3 во время inference.

Batch Processing

Прогнозирование выполняется автоматически через Airflow.

PostgreSQL Output

Результаты сохраняются в отдельную таблицу predictions.
