01 — Business Problem

Необходимо определить, какие объявления имеют высокий потенциальный спрос относительно других объектов в том же городе и сегменте.

SmartScore должен использоваться как дополнительный сигнал для ранжирования объявлений и помогать улучшать качество выдачи.

Бизнес-цель — повысить релевантность выдачи, улучшить пользовательский опыт и снизить долю неактивных или нерелевантных объявлений.

02 — Data

Listings 661K+
Cities 10
Features 64

Основная таблица listings содержит характеристики объектов, параметры хозяев, цены, рейтинги, доступность и информацию об отзывах.

Дополнительно использовались данные calendar и reviews.

03 — Target Engineering

Целевая переменная is_high_demand строилась относительно сегмента город + тип жилья.

Для каждого сегмента рассчитывались медианы количества отзывов, цены и рейтинга.

Объявление считалось high-demand, если одновременно:

  • количество отзывов выше медианы сегмента;
  • цена не ниже медианной;
  • рейтинг не ниже медианного.

Признаки, участвующие в формировании target, а также потенциально содержащие информацию о будущем спросе, исключались из модели для снижения риска data leakage.

04 — Feature Engineering

Для модели были сформированы дополнительные признаки, описывающие характеристики объекта и владельца.

price_per_person avg_stay_nights stay_ratio host_age_days host_quality_score name_length name_word_count desc_length amenities_count bathrooms_per_guest beds_per_guest

Для категориальных признаков использовалась встроенная обработка CatBoost без One-Hot Encoding.

Текстовые поля очищались и передавались в CatBoost для внутреннего преобразования.

07 — Evaluation

Финальная модель показывает высокий Recall — 0.9796, то есть обнаруживает большую часть объявлений, относящихся к целевому классу.

При этом PR-AUC составляет 0.9378, что является особенно важной метрикой при дисбалансе классов.

08 — Production Architecture

Batch inference запускается через Apache Airflow. Данные и ML-артефакты хранятся отдельно, а результат расчёта возвращается в PostgreSQL.

09 — MLOps

  • Apache Airflow используется для оркестрации batch inference.
  • ML-модель и preprocessing сохраняются в S3.
  • Данные загружаются из PostgreSQL.
  • Результаты инференса сохраняются обратно в PostgreSQL.
  • Pipeline поддерживает повторный запуск без дублирования результатов за одну дату.

10 — Result

Результатом работы системы является числовой SmartScore для каждого объявления.

Score сохраняется вместе с идентификатором объекта и датой инференса: 

listing_id
score
inference_date

Такой score может использоваться как дополнительный сигнал для ранжирования объектов и последующих продуктовых сценариев.
